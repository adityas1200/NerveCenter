## Remaining decisions

The queue choice and catch-up policy in [ADR 0011](../adr/0011-own-durable-scheduled-job-queue.md), Sonic recovery in [ADR 0013](../adr/0013-sonic-task-ownership.md), and routine task ownership in [ADR 0015](../adr/0015-idempotent-scheduled-routine-start.md) are approved. The current deployment has one authoritative backend per workspace; the queue coordinates scheduled claims, while external writes still require provider idempotency or reconciliation for an exactly-once guarantee.

The approved [ADR 0016](../adr/0016-migrate-ticket-and-monitor-fetch-timers.md), [ADR 0017](../adr/0017-idempotent-ticket-triage-start.md), and [SPEC-platform-14](../../specs/platform/scheduled-fetch-jobs.md) now cover ticket imports and monitoring fetches. Automatic triage and monitoring detection remain local, separate from retryable provider work. The remaining verification is the full test gate and live traffic, provider-call, freshness, and restart measurements in a representative deployment.

## Benchmark method and acceptance

Source-derived steady-state request estimate for one visible ticket tab: before this work, 13 shell requests/minute plus four ticket-list GETs = about 17/minute. With the idle agent-status cadence and a connected ticket change feed, eight shell requests/minute remain, the ticket list makes no interval GET, and the tab holds one SSE response. That is about nine fewer repeated HTTP requests per minute (53%) while connected. On Data Quality, the prior 15–16/minute estimate falls to about 10/minute after removing its duplicate refresh and slowing idle agent status. These figures come from configured intervals and focused fake-clock tests; they are not a live traffic measurement and exclude initial loads, reconnects and manual actions.

- Capture a five-minute browser Network trace on each representative page, visible and hidden, with one then two tabs. Count requests by endpoint, 429s, retries, and bytes. Use the same seeded project and stable data before and after each phase; exclude page-load bursts from steady-state rates.
- Use stub provider clients and a clock to count Databricks SQL/job, Snowflake, Jira, ServiceNow, GitHub CLI, and object-store calls per project and due interval. Record DQ rows read and fetch duration because the full retention window dominates cost.
- Measure freshness as time from committed job/result to visible UI update: connected SSE and disconnected fallback separately. Measure restart recovery and two-worker duplicate/loss counts with intentionally interrupted jobs.
- Pass when DQ has one scheduled refresh POST and one post-refresh reconciliation POST per visible minute, hidden tabs issue no scheduled provider refresh, each configured project/connector is due independently, a job key has one active claim across workers, queued work survives restart, and manual buttons/routines/automations still complete. Preserve API response shapes and permission checks.

Critical-path tests are listed at each gate. Existing tests should stay intact; edits to existing test files require the confirmation rule in `AI_CODE_GUIDELINES.md`. Full backend and frontend suites run before each implementation handoff.

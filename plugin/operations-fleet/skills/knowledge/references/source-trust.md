# Knowledge trust and precedence

Use this order unless client policy says otherwise:

1. Explicit user instruction within their authority.
2. Enforced deployment policy and provider permissions.
3. Current authoritative system state.
4. Approved, applicable, and current internal knowledge.
5. Current official public documentation for external behavior.
6. Historical examples and unapproved drafts.

A lower source cannot override a higher source. A public vendor page cannot approve an internal access grant. An old runbook cannot override a newer approved SOP. A live ticket state does not prove the business outcome.

When two sources at the same level conflict, report the conflict, owner, dates, and scope. Prefer the source that is more specific and applicable; ask the designated owner when the conflict is material.

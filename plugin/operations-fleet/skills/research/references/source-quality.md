# Source quality

Use the strongest source that can answer the exact question.

## Preferred order

1. Current official documentation, standards, regulations, security advisories, release notes, status pages, and original research.
2. Official repositories, issue trackers, and provider-authored examples.
3. Reputable independent technical or academic sources.
4. Community discussion only when it provides unique evidence; verify important claims elsewhere.

## Checks

- Is the page current and applicable to the exact product, cloud, region, edition, API version, and jurisdiction?
- Is it normative documentation or only an example?
- Does a newer page supersede it?
- Is the stated date the event date, publication date, or last-updated date?
- Is the claim directly supported or inferred?
- Do primary sources disagree?

For a material conclusion, cite the exact source near the claim. When no authoritative answer exists, state what was searched and what remains unknown.
